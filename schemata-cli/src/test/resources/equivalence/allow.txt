# Every output that `schemata upgrade` plus the 2.0 compiler writes differently from the 1.4.0
# compiler, for every 1.x schema as it stood at v1.4.0: the examples, the corpus, both sides of each
# evolution case, and the diagnostics fixtures. One line per path and reason: the case directory,
# the target's output path (or `diagnostics`, or a fixture's `codes`), then the reason.
#
#   reference by key   a field typed as a keyed model carries the key, and the key's type is
#                      declared beside the model (Protobuf, XSD, JSON Schema, OpenAPI)
#   on delete          an ON DELETE clause on a foreign key
#   type notes         the `schemata:` note on an emitted field is in 2.0 spelling
#   message text       a diagnostic says model or schema, spells a type as 2.0 does, or warns
#                      about a field a reference now emits
#   keyword rename     an identifier that is a 2.0 keyword is renamed `<name>_value`
#   retired check      a diagnostics fixture whose 1.x check 2.0 moved into an option or dropped;
#                      the fixture was deleted with it (its `codes` differ)
#   upgrade refuses    a diagnostics fixture writing something 2.0 cannot say, which `upgrade`
#                      reports instead of converting (its `codes` differ)
